# 验收标准：REQ-002.4 `.tools` 工具链自举机制

> 每条 AC 必须可机械验证。测试项目放 `/tmp/qa-0024/` 下构造，不污染真实仓库。
> 记 `QA=<qa 入口的绝对路径>`，`PROJ=<测试项目根>`。

### AC-001: `bin/qa` 在包内且可执行
- **前置条件**: 无
- **测试步骤**: `npm pack --dry-run` 看文件清单；再跑 `node <包根>/bin/qa --help`
- **预期结果**: 包内含 `bin/qa`；`--help` 退出码 0，输出列出全部子命令
- **类型**: 功能

### AC-002: `qa list` 列出清单工具与状态
- **前置条件**: `PROJ/.tools/manifest.json` 声明 2 个工具
- **测试步骤**: `qa list --project <PROJ>`
- **预期结果**: 退出码 0；两个工具都在输出里，各自带状态（未安装时为 `missing`）
- **类型**: 功能

### AC-003: `qa doctor` 区分四种状态
- **前置条件**: 一个已装好的工具（`ok`）、一个声明了但未安装的（`missing`）、一个安装命令真的跑起来但失败的（`failed`）、一个下载源不可达的（`unavailable`）
- **测试步骤**: `qa doctor --project <PROJ>`
- **预期结果**: 退出码非 0；输出能区分 `ok` / `missing` / `failed` / `unavailable` 四种状态，每个工具一个明确结论
- **边界要求**: `failed` 与 `unavailable` 的分界必须确定且可复现 —— **源不可达**（连接被拒 / DNS 失败 / 网络受限 / 非 404-410 的 HTTP 错误码）判 `unavailable`；**源存在但地址或版本不对**（HTTP 404 / 410）、校验和不匹配、安装命令报错判 `failed`。用外部域名 404 冒充"不可达"是无效测试
- **类型**: 功能

### AC-004: 版本锁定是强制的
- **前置条件**: 清单里放一个 `spec` 为 `"bandit>=1.7"`（未锁版本）的工具
- **测试步骤**: `qa install --project <PROJ>`
- **预期结果**: 拒绝安装，退出码非 0，报错指出"版本未锁定"
- **类型**: 功能

### AC-005: `install` 命令不得写到 `.tools/` 之外
- **前置条件**: 清单里放一个 `install` 指向项目外路径的命令（如 `pip install --user {spec}`）
- **测试步骤**: `qa install --project <PROJ>`
- **预期结果**: 拒绝安装，退出码非 0，报错指出安装路径越界
- **类型**: 安全

### AC-006: Python 工具装进 `.venv`，不污染系统
- **前置条件**: 清单里有一个 `kind: python` 的工具
- **测试步骤**: `qa install` 后，检查 `.tools/.venv/` 存在；再跑**系统** `python3 -c "import <该工具的模块>"`
- **预期结果**: 系统侧 import **失败**（`ModuleNotFoundError`）；隔离性成立
- **类型**: 安全

### AC-007: Node 工具装进 `.tools/node`，不污染系统
- **前置条件**: 清单里有一个 `kind: node` 的工具
- **测试步骤**: `qa install` 后，检查 `.tools/node/` 存在；再跑**系统** `command -v <tool>`
- **预期结果**: 系统侧**无输出**（不可见）；隔离性成立
- **类型**: 安全

### AC-008: `qa which` 指向 `.tools/` 内的路径
- **前置条件**: 一个已安装的工具
- **测试步骤**: `qa which <name> --project <PROJ>`
- **预期结果**: 退出码 0；打印的路径位于 `<PROJ>/.tools/` 之下
- **类型**: 功能

### AC-009: `qa run` 是白名单式的
- **前置条件**: 清单里没有 `foo` 这个工具
- **测试步骤**: `qa run foo -- --version`
- **预期结果**: 退出码非 0，报错指出该工具不在清单中，**且未执行任何命令**
- **类型**: 安全

### AC-010: `qa run` 执行的是 `.tools/` 里那份，不是系统的
- **前置条件**: 装一个与系统同名同名的工具；用 `qa which` 与 `qa run` 分别确认
- **测试步骤**: `qa which <name>` 与 `qa run <name> -- --version`
- **预期结果**: 两者的路径都指向 `<PROJ>/.tools/` 下的副本
- **类型**: 功能

### AC-011: 工具不可用时**不得静默跳过**
- **前置条件**: 清单里一个装不上的工具（如 `kind: binary` 且来源不可达）
- **测试步骤**: `qa install` 后 `qa doctor`
- **预期结果**: 退出码非 0；该工具状态为 `failed` 或 `unavailable`（**不是** `ok`，也不是"跳过"）；错误信息说清原因
- **类型**: 功能

### AC-012: 安装幂等
- **前置条件**: 一个已安装的工具
- **测试步骤**: 再跑一次 `qa install`
- **预期结果**: 退出码 0；报告"已安装，跳过"；不重复下载、不改变已装内容
- **类型**: 可靠性

### AC-013: `state.json` 记录版本与来源
- **前置条件**: 一个已安装的工具
- **测试步骤**: 读 `<PROJ>/.tools/state.json`
- **预期结果**: 含该工具的 `name` / `version`（与清单 `spec` 一致）/ `source` / `installed_at`
- **类型**: 功能

### AC-014: `.gitignore` 精确忽略，manifest 进 Git
- **前置条件**: 一个含 `.tools/` 的项目
- **测试步骤**: 跑 `git check-ignore -v` 对 `.tools/.venv/x` 与 `.tools/manifest.json`；再跑 `git status --porcelain` 看 `.tools/manifest.json` 是否出现在待提交列表
- **预期结果**: `.tools/.venv/x` 被忽略；**`.tools/manifest.json` 不被忽略**且出现在待提交列表
- **类型**: 功能

### AC-015: 零依赖 + 退出码语义
- **前置条件**: 源码级检查
- **测试步骤**: 检索 `bin/qa` 的第三方依赖调用；分别触发成功、校验失败、调用方式错误三种情形
- **预期结果**: 无第三方依赖；退出码分别为 `0` / `1` / `2`
- **类型**: 非功能

### AC-016: 全部交付文件都进了 npm 包（分发链路）
- **前置条件**: 无
- **测试步骤**: `npm pack --dry-run`，取完整文件清单；逐个核对本 REQ 新增/修改的文件是否在清单里
- **预期结果**: `bin/qa`（及其实现文件）、工具链契约文档**全部在清单里**。**任何一个缺失即 FAIL**
- **类型**: 功能

> **为什么这条必须单独列**：REQ-002B 开发阶段实测发现，产物放包根时 `npm pack --dry-run` 显示 `total files: 10`，包根文件完全没进包 —— `package.json` 的 `files` 只含 `skills/ bin/ README.md LICENSE`。交付物存在于工作区 ≠ 存在于用户机器上。


### AC-017: `qa doctor` 是只读的（不触发安装、不改 `.tools/`）
- **前置条件**: 一个声明了工具但**未安装**的项目
- **测试步骤**: 记录 `.tools/` 目录树指纹 → 跑 `qa doctor` → 再记录一次；并检查是否生成了 `.venv` / `state.json`
- **预期结果**: 目录树前后**逐项不变**；未生成 `.venv`；未生成 `state.json`
- **理由**（D3）: 体检命令却改了系统状态，是不可预期的副作用 —— 尤其在 CI 里 `doctor` 常被当前置检查跑
- **类型**: 功能

### AC-018: `qa run` 拒绝执行 `.tools/` 之外的入口（`entry` 路径穿越）
- **前置条件**: 清单条目声明 `"entry": "../../evil.sh"`，该文件可执行且位于 `.tools/` 之外
- **测试步骤**: `qa run <name> -- x`；再看 `qa which <name>`
- **预期结果**: `qa run` 退出码非 0；输出中**不得出现**被越界文件的任何输出；`qa which` **不得**把越界路径当成"隔离副本里的可执行文件"报出
- **理由**: 白名单只约束"名字"（`name` 在清单里），被白名单放行的**实际被执行的文件**却不受任何约束 —— 那不是白名单，是一层纸。契约的根本承诺是"只跑 `.tools/` 里那份"
- **类型**: 安全
