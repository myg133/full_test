## D1　`failed` 与 `unavailable` 的分界

**背景**：状态只有 `ok` / `missing` / `failed` / `unavailable` 四种，没有"跳过"。
`failed` 与 `unavailable` 对下游（各能力域 skill）的**义务相同**——都必须把对应能力
标为「不可用 / 未覆盖」，不得报告为「未发现问题」。但两者的**诊断含义**不同，
必须能被调用方预判。

**决策**：按**根因**分，不按表面现象分。

| 根因 | 状态 | 说明 |
|---|---|---|
| 下载源**不可达**（连接被拒 / DNS 失败 / 网络受限 / 超时） | `unavailable` | 环境问题，换个环境可能就好了 |
| 下载源可达但返回**非 404/410 的错误码**（5xx 等） | `unavailable` | 来源当前不可用 |
| 下载源可达但返回 **404 / 410**（地址或版本不存在） | `failed` | 清单写错了，是**可修的配置问题** |
| `install.sha256` 不匹配 | `failed` | 产物被篡改，必须失败 |
| 安装命令执行报错（包不存在、编译失败等） | `failed` | 装不上，但原因明确 |
| 运行时缺失且回退也不可用（无 uv+pip / 无 bun+npm） | `unavailable` | 本环境装不了这条路 |
| 声明了但未安装 | `missing` | 还没试过 |
| 已安装但 `verify` 未通过 | `failed` | 装了但不能用 |

**理由**：分界的**唯一目的**是让人知道"该改环境还是该改清单"。
404 说明"你给的地址不对"——这是可以立刻修的具体错误，判成"环境装不了"会误导
下游去换环境。连接被拒/DNS 失败则相反——地址写得再对也拿不到，只能换环境或换路线。

**被否决的方案**：把 404 也判成 `unavailable`。
理由是它会让"清单里版本号写错了"这种最常见的配置错误，被误报成"本环境不支持该能力"，
把**可修的配置错误**降级成**不可修的环境结论**。

**对验收的影响**：验收脚本必须**分别**造出"源不可达"和"源 404"两个场景。
用外部域名 404 冒充"不可达"是**无效测试**（它天然落在 `failed` 分支）——
这正是本 REQ 验收初版 AC-003 失败的原因。
为保证判定可复现、不依赖外网，验收场景一律用**本地端口**：
一个"起过又关掉"的端口（连接被拒 → `unavailable`）、一个"起着的 404 服务"（→ `failed`）。

## D2　`binary` 的 `spec` 形态

**背景**：硬规则 1 要求版本必须锁定，但 `python` / `node` / `binary` 三种 kind 的
`spec` 形态不同，契约初版只写了前两种。

**决策**：

| kind | `spec` 形态 | 示例 |
|---|---|---|
| `python` | `name==version` | `bandit==1.7.7` |
| `node` | `name@version` | `semver@7.7.2` |
| `binary` | **纯版本号**，或**完整下载 URL** | `1.0.0` / `https://host/tool-linux-amd64` |

`binary` 的版本号必须是精确版本（不接受 `>=` / `latest` / `^` 等）。
下载 URL 的形态下，URL 本身就是版本标识。

**理由**：`binary` 路线没有包管理器，**没有** "name@version" 这个概念可写；
只有"装哪个版本"（纯版本号）或"从哪拿"（URL）两种可能。
不写清楚，照文档造出来的清单会被校验器拒——这与 REQ-002A 的 `cycle_id` 同型。

## D3　`qa doctor` 不触发安装

**决策**：`qa doctor` 与 `qa list` 都是**只读**体检，不做任何安装动作；
`qa install` 才是唯一会改 `.tools/` 的子命令。

**理由**：体检命令却改了系统状态，是不可预期的副作用——尤其在 CI 里，
`doctor` 常常被当成前置检查跑。状态判定因此是**纯函数**：
由「清单 + state.json + `.tools/` 里的实际可执行文件」三者推出，
不依赖"要不要装一下试试"。

**推论**：所以"未安装"在 doctor 上必须可达为 `missing`（而不是被安装尝试吞掉），
这直接决定了 `missing` 的可达性要求。

## D4　`.gitignore` 用 `.tools/*` 而非 `.tools/`

**决策**：`.gitignore` 写 `.tools/*` + `!.tools/manifest.json`。

**理由**：写 `.tools/` 会让整个目录被忽略，`!.tools/manifest.json` 这条否定规则
**失效**，清单静默不进版本库——工具链定义丢了却没有任何报错。
用 `.tools/*` 逐项忽略，否定规则才生效。
