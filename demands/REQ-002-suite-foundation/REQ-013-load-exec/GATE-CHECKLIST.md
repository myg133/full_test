# REQ-013 独立审门清单（`GATE-CHECKLIST.md`）

> **纪律**：本清单是**需求方**用来审**验收门**的工作单。门是**交付物**，必须被当作**被验对象**对待（D65）。
> **顺序**：门到货 → **需求方独立审门**（本清单）→ 通过才派 Dev。
> **不许**「门跑绿了就算过」—— 门自己可能就是错的（REQ-012 实测：**第一轮完整模式 5 个变异体无效**，
> 根因是 4 个门侧缺陷，包括拼写错误 `not_provired`、自证指纹语义归一化掩盖真实检出、负控与自证同用一套指纹）。

---

## 1. 审门分组（**8 组，全部必跑**）

| 组 | 名称 | 做什么 | 期望 |
|---|---|---|---|
| **A1** | 快跑 | 门跑**快跑模式**（只跑基线） | `38 PASS / 0 FAIL`，rc=0 |
| **A2** | 完整模式 | 门跑**完整模式**（基线 + 全部变异体） | `38 PASS / 0 FAIL` + **全部变异体检出** + **负控未检出**，rc=0 |
| **A3** | 无实现优雅降级 | 对**空实现**（删掉 `run-load-test.mjs`）跑 | 不崩溃；rc=1；有明确 FAIL 报告；**门的 stderr 里 0 处 bash 错误行**、0 处崩溃迹象 |
| **A4** | 错 sha | 用**错的** `QA013_SCRIPT_SHA` 跑 | `0 PASS / 1 FAIL`，rc=1 |
| **A5** | 只读 | 跑前跑后各算被验包目录树 sha256 | **逐字相同**（门不得改被验包） |
| **A6** | 幂等 | 同一被验包连跑两次 | 两次「逐条结论」**逐字一致** |
| **A7** | 判据对照 | 门的判据与 `acceptance.md` 的 **38 条**逐条对照 | **无漏判、无多判、无编号错位**；条数 == 38 |
| **A8** | 外部探针 | 用**门之外**的探针工装打门与交付物 | 见 §4（抓门抓不到的缺陷） |
| **A9** | 独立语义复算 | 用需求方侧复算器（`~/.local/share/agent-runtime-data/tmp/req013/t1/recompute.py`）复算产物 | **不一致 0**（不可判定项须显式列出） |

⚠️ **A2 的判定口径**：**新增失败键** = 变异体失败键 − 基线失败键（基线失败键**只取 `^FAIL` 行**）。
⚠️ **不得用对称差**（REQ-012 的教训）。
⚠️ **每路必须独立工作根**（`QA013_WORK_ROOT`）⇒ **并发跑多个门会产生无因果关系的额外 FAIL 键**。

## 2. REQ-013 **特有**的易错点（**逐条核**）

> 这些是**本 REQ 特有**的（不是通用检查项）。每条都对应一条判据或一条决策。

| # | 易错点 | 核法 | 关联 |
|---|---|---|---|
| **1** | ⚠️ **漏设 `statusCallback`** ⇒ HTTP 错误码全塌成 `-1` | 跑一个**桩返回 500** 的场景 ⇒ `observed.error_codes` 必须是 `{"500": N}`，**不是** `{"-1": N}` | AC-009 / B6 |
| **2** | ⚠️ **两侧计数做等式判定** | 看 AC-011 的实现：必须是**上界**（`≤ concurrency + 5`），**不是** `==` | AC-011 / D198 |
| **3** | ⚠️ **判定只看退出码** | 桩中途挂掉时，判定**不得**判 `met`（实测：loadtest rc 仍为 0） | AC-009 / D197 |
| **4** | ⚠️ **吞吐与错误率不联合判** | 全部失败时 `effective_rps` 依然很高 ⇒ `error_rate` 判 `not_met` 时吞吐**不得**单独报达标 | AC-020 / C4 |
| **5** | ⚠️ **`max_concurrency` 拿 `concurrency` 或 `clients` 冒充** | 该键的 `observed` 必须是 `null`、`verdict` 必须是 `undetermined` | AC-018 / D189 |
| **6** | ⭐ **默认桩下把延迟 / 错误率判成 `met`**（本 REQ 最核心的红线） | `execution.stub.delay_ms == 0 且 error_rate == 0` 时，四个延迟/错误率键**必须** `undetermined` | AC-019 / D199 |
| **7** | ⚠️ **`.loadtestrc` 渗透** | 在夹具项目根放一个 `.loadtestrc`（改 `concurrency` / `method`）⇒ 跑出来的 `executed_params` **不得**受它影响 | F4.3⑤ / D202 / B12 |
| **8** | ⚠️ **URL 替换连 path 一起换** | `executed_url` 的 path + query 必须与计划里的**逐字**相同 | AC-012 / D194 |
| **9** | ⚠️ **非回环地址没被拒** | 计划里的 URL 指向 `example.com` ⇒ rc=1 + 点名，**不产产物** | AC-032 / D194 |
| **10** | ⚠️ **桩残留** | 跑完后探 `execution.stub.origin` 的端口 ⇒ 必须**连不上** | AC-035 / D196 |
| **11** | ⚠️ **桩侧观测写成累计** | 第 2 条 invocation 的 `requests` 不得 ≥ 第 1 条的 `requests`（累计口径的特征） | AC-014 / F3.3 |
| **12** | ⚠️ **改成并发执行** | 两条 invocation 的时间窗**不得**重叠（`last_at_ms ≤ 下一条 first_at_ms`） | AC-013 |
| **13** | ⚠️ **CLI 模式冒充 API 模式** | `--mode cli` 跑完后 `execution.mode` 必须是 `cli_verbatim` | AC-027 / D192 |
| **14** | ⚠️ **CLI stdout 解析不出却编数** | 给一个**畸形**的 stdout ⇒ 必须 rc=1 + 点名，**不得**编造分位 | AC-027 / D201 |
| **15** | ⚠️ **API 模式标成 `cli_verbatim`**（或反之） | `execution.mode` 与实际路径必须一致 | AC-005 / AC-026 |
| **16** | ⚠️ **反解 argv 漏项 / 单位错** | `executed_params.timeout` 必须 == `-d` 的**毫秒**值；`maxSeconds` == `-t` 的值 | AC-026 / D200 |
| **17** | ⚠️ **结果产物多写顶层键** | 顶层键集合**恰好 8 个** | AC-002 / D204 |
| **18** | ⚠️ **`results_sha256` 剔除字段错** | 门自己复算必须一致 | AC-004 |
| **19** | ⚠️ **覆盖已有产物** | 跑第二次必须 rc=1 且原文件 sha256 不变 | AC-029 |
| **20** | ⚠️ **工具缺失仍产出产物** | 挪走 `.tools/` ⇒ rc=1 + 点名 `loadtest` 与 `qa install`，**零产物** | AC-033 / D206 |
| **21** | ⚠️ **`undetermined` 被写成 `passed`** | 产物里不得出现取值 `passed` / `failed` / `blocked` / `skipped` 的判定 | AC-025 / F6.3 |
| **22** | ⚠️ **出现生产容量表述** | 产物全文不得出现「生产」「容量达标」「可承载」「production」「capacity」 | AC-024 / D205 |
| **23** | ⚠️ **改写了输入** | `plans/` / `scenarios/` / `suites/` / `environments/` 跑前跑后逐字相同 | AC-028 / F8.4 |
| **24** | ⚠️ **`.tools/manifest.json` 的 `verify.match` 大小写写错** | 夹具的清单必须写 `"Loadtest"`（大写 L）⇒ 否则 `qa doctor` 判 failed ⇒ 工具被判不可用 | 夹具 §0.1 / PROBE-FACTS F8 |
| **25** | ⚠️ **`python` runner 被判成 `met`** 或给它编一个 `observed` | WL-003 的 invocation：`observed` **缺席**、`verdict == "undetermined"`、`thresholds` 空数组、**证据目录里有它的子目录** | AC-041 / D203 |
| **26** | ⚠️ **注入后仍判 `undetermined`**（过度保守 ⇒ 判定链永远无效） | `--stub-delay-ms 50` ⇒ 延迟三类 + 错误率**恢复可判**；`--stub-error-rate 1` ⇒ 错误码是 `"500"` 不是 `"-1"` | AC-039 / AC-040 |
| **27** | ⚠️ **`execution` 段的 `cli` 键口径搞反** | api 模式 ⇒ `execution` 键集合**恰好 6 个**（`cli` 缺席）；cli 模式 ⇒ **恰好 7 个** | AC-005 / F7.3 |
| **28** | ⚠️ **禁词表把 `capacity` 也禁了** | `thresholds_source = "capacity-targets"` 是**来源标记**，**不在**禁词表 ⇒ 禁了会误伤正确实现 | AC-024 |

## 3. 门的**自证**要求（审门时逐条确认）

| # | 要求 | 核法 |
|---|---|---|
| 1 | **变异体必须自证生效** | 每个变异体注入前后做**字节级 + 权限位**指纹比对；没生效即判红 |
| 2 | **指纹不许语义归一化** | ⚠️ REQ-012 曾因「归一化 + 提前 continue」掩盖真实检出 ⇒ 审门时**专门查**这一点 |
| 3 | **负控与自证不得同用一套指纹** | ⚠️ REQ-012 曾因此导致负控永远「没生效」⇒ 审门时**专门查** |
| 4 | **负控必须未检出** | 无害改动 ⇒ 门**必须**判绿 |
| 5 | **判据不许恒真** | 每条判据至少一个变异体；「哪些判据没有变异体」必须有**明确理由**（否则算漏） |
| 6 | **判据不许靠查源码字面量自证** | 抽查若干条：判据的判定依据必须是**产物内容**或**可观测行为**，不是「源码里有没有这个词」 |
| 7 | **不可判定必须显式** | 判不了时必须标「不可判定」并 rc=1，**不得**判 passed |
| 8 | **不许写不可满足的判据** | 抽查：判据的期望值必须是实现方**做得到**的（例：AC-011 只判上界 ⇒ 两侧恰好相等**允许**） |

## 4. A8 外部探针（**门抓不到的缺陷**）

> **REQ-012 的教训**：门与 T1 复算**全部漏检**了「校验器比契约更严」这类缺陷 ⇒ 由**外部探针的负控**（无害改动 ⇒ 必须仍全绿）抓出。

⇒ 本 REQ 的外部探针**至少**要覆盖：

| # | 探针 | 期望 |
|---|---|---|
| P1 | **无害改动**（改 `generated_at` 的格式、加一个允许的键、换个 plan 的 `scenario_name`） | 门必须**仍判绿**（不误伤） |
| P2 | **桩行为注入后**（`--stub-delay-ms 50`） | 延迟类与错误率类阈值**恢复可判**（D199 的后半句）⇒ 若仍 `undetermined` ⇒ 门抓不到「注入生效」 |
| P3 | **阈值边界翻转**（把阈值改到观测值之上 / 之下） | 判定必须跟着翻转（`met` ⇄ `not_met`）⇒ 验「判定真的用了观测量」 |
| P4 | **桩侧计数被改大** | AC-011 的上界必须抓到 ⇒ 验「差值上界真的在用」 |
| P5 | **CLI 模式跑一次** | 与 api 模式的产物**结构**一致、`mode` 与降级标注不同 ⇒ 验「两模式真的都通」 |

## 5. 审门结论的写法（**收口时必须落进 `status.md`**）

- 逐组结论（A1~A8）：**每组**的期望 vs 实际 + rc；
- 抓到的**门侧缺陷**逐条定位（文件 + 行号 + 现象 + 根因）；
- 回修后的复跑结果；
- **不可判定项**必须显式列出，**不许**含糊过去。
