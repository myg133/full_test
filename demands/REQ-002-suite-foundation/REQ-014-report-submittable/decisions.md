# REQ-014 · 决策记录

> 决策号 **D211 ~ D218**（沿用本仓全局连续编号；REQ-013 用到 D210）。
> 格式沿用既有约定：`| Dxxx | 议题 | 裁定 |`。

| 决策号 | 议题 | 裁定 |
|---|---|---|
| D211 | **报告默认输出位置改到项目根** | **采纳**：默认 = `<项目根>/reports/<run_id>/`。**显式取代** REQ-010 的 AC-025 ①「默认输出在 `<run_dir>/report/`」—— 那是同一 skill 的**行为演进**（不是跨 skill 冲突），故直接改旧契约与旧门，并如实登记门 sha 变化。**理由**：用户实机反馈的根因正是「产物区被 `.gitignore` 忽略 ⇒ 报告不可提交」；报告是**交付物**，交付物不该落在「明确不进 Git」的地方。 |
| D212 | **项目根怎么定位** | **采纳三段式**：① `--project-root` 显式 > ② 从 run_dir 形态 `<root>/.test-artifacts/<id>` 反推（root = 上两级）> ③ 两条都不成立 ⇒ **报错退出 rc=1 并点名 `--project-root`**。**不猜**：不许默认拿 cwd 当项目根，也不许默认拿 run_dir 当项目根。**理由**：猜错的后果是「报告落在一个用户没预期的目录」——静默的错比报错更坏；且 REQ-010 夹具的 run_dir 形态本就不合法，反推路径必须有明确的失败语义。 |
| D213 | **`content` 存脱敏后的原始文本，还是解析后的对象** | **采纳原始文本（string）**。**理由**：① 字节级保真 ⇒ `content_sha256` 可从 `content` 直接重算；② 无敏感内容时 **`content_sha256 == sha256` 严格成立** —— 这条不变量同时是「脱敏器不误伤」的机械证明（AC-011）；③ 解析再序列化会引入格式化差异，让「未脱敏」这个状态无法判定；④ md 渲染时再解析并 pretty 打印，**人看的可读性不受影响**。代价：`report.json` 里 JSON 证据是转义字符串（体积略涨、机器读要二次解析）——可接受。 |
| D214 | **被测目标的 IP / 端口 / 用户名要不要脱敏** | **保留，不脱敏**。**理由**：它们是**被测对象标识**与**业务账号**，不是凭证；抹掉之后报告无法说明「测的是哪台机器、哪个账号」，失去核心价值。用户拍板的「一律脱敏」在选项描述里明确限定为「口令/凭证换占位符、绝对路径换相对路径」——本决策是对该选项描述的**精确化**，不是偏离。⚠️ 已登记为遗留项 L-02：若报告将来要进**公开**仓库，需另开「按仓库可见性分级脱敏」的维度。 |
| D215 | **既有的 `failures[].evidence[]` 要不要一起改** | **不改**（保持逐字取自产物，含相对 run_dir 的 `path`）。本 REQ 只做**增量**：新增 `evidence.files[]` 作为「实查 + 内联」的权威视图。**理由**：改动既有字段含义会牵连 REQ-010 的 AC-013 与其门的对应判据；且两个视图并存反而更有用 —— `failures[]` 里是**产物自述**，`files[]` 里是**实查事实**，两者不一致本身就是证据层该抓的问题（`evidence_mismatch`）。 |
| D216 | **`redaction` 段的计数怎么填** | **如实计数**，不许为了「看起来在脱敏」而虚报。产物里没有敏感内容时，`redacted_fields == 0` 且 `redacted_values == 0`，`rules_applied` 仍列出**实际启用**的规则（规则是代码里装着的，不是本次命中的）。**理由**：虚报的脱敏计数比没有脱敏段更危险 —— 读者会以为「报告已经全面处理过了」。 |
| D217 | **根因在 `test-execute` 侧，本 REQ 要不要顺手改** | **不改**。`reproduction.command` 的明文口令在**产物生成侧**才是根因，但修它要改 `test-execute` 的契约与门（属 REQ-010 同族）⇒ **不在本 REQ 范围**。本 REQ 在**报告侧**做纵深防御（值模式能兜住内嵌 JSON 口令），并把根因登记为遗留项 L-01。**理由**：范围蔓延会让本 REQ 的验收链变长、风险面变大；纵深防御本身也值得独立存在（报告可能消费第三方产的 `results.json`）。 |
| D218 | **脱敏器要不要跨 skill 复用 `test-execute` 的 `lib/redaction.mjs`** | **不 import，在 `test-report` 内自包含实现**。**理由**：① 本仓既有实现**没有跨 skill import 代码的先例**（`security-plan` / `regression-plan` 都只通过**产物契约**耦合，不 import 对方代码）；② REQ-010 的 AC-026 有一条硬判据「相对 import 只许指向本 skill 内」—— import 别的 skill 会直接判红；③ 重复实现的代价（两处规则要同步）小于破坏 skill 隔离的代价。**代价如实登记**：规则集在本仓里有两份（`test-execute` 与 `test-report`），后续若要统一，须另立 REQ。 |
