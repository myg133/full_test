## 6. 取舍清单（**供需求方逐条裁定**）

| # | 取舍 | 理由 | 若不认可的后果 |
|---|---|---|---|
| T-01 | 「OWASP 十类**每类都有交代**」而不是「A01~A10 每类都≥1 条威胁」 | 「确实不适用」是语义判断，门没法机械核「实现选的那类是不是真的不适用」；写死某一类必须 N/A 会变成**假判据** | 需重写 AC-011 / AC-012 / AC-027 与夹具 §0.1 |
| T-02 | `roles` / `resources` 定为上下文的**必填**段 | F4 的矩阵要「角色 × 资源 × 动作」，角色/资源必须有出处；可选 ⇒ 实现只能捏造，矩阵成自说自话 | 需放宽 F1.2 并把 AC-015 改成「矩阵可用匿名角色」 |
| T-03 | 威胁条目字段集**封闭 12 个** | 封闭才能机械核；上游 `cases.json` 的封闭 7 个也是同类做法 | 需放宽 AC-010（字段集改为「必填项齐全」而不是「恰好这些」） |
| T-04 | `basis` 只用两值（`expected` / `gap`），不加 `unknown` | 多一个 `unknown` 就是逃逸口（声明成 unknown 就不用对账了） | 需同步改 AC-016 双向对应规则 |
| T-05 | 越权类 = `category == "elevation_of_privilege"`（STRIDE），不用 OWASP 码 | OWASP A01 下可以有多种 STRIDE 类别；用 STRIDE 判定「越权」更直接 | 需改 AC-016 的双向对应 |
| T-06 | 产物 `cases[].status` **恒为 `active`**（D124，需求方订正） | 上游对非 active **硬拦**（缺 `revision` ⇒ FAIL）；且刚派生的用例没有前序版本，声称「被改过/已废弃」是假的；`blocked` 是执行阶段的判定 | 需放宽 AC-020 并接受「门比上游宽 ⇒ 假绿」的风险 |
| T-07 | `method` 的**存在性**由门用独立复算器判（D125，需求方订正） | 上游 L398 **只查格式**，不查方法是否在方法库里；「上游会拦」是假话 | 需删 AC-020 的该项 ⇒ 假绿洞 |
| T-08 | 顶层封闭 7 个由门判（D109） | 上游 v2 严格模式把**缺失**升级为 ERROR，但**不拦多余顶层字段** | 需删 AC-020 的该项 ⇒ 假绿洞 |
| T-09 | 夹具的环境**不写 `driver`**（D126，需求方订正） | 环境 `driver` 会**覆盖** `suite.json` 的 `executor`；写了就会误配对到 `api`/`mock` ⇒ 「能跑通」是假象 | 夹具一旦写了 `driver`，任何基于 dry-run 的结论都不可信 |
| T-10 | AC-024 判**加载层**（`loadSuite`/`loadCases`/`selectCases` + `validate-cases.mjs`），**不判** `--dry-run`（D111） | `security` 执行器未实现，`--dry-run` 会先抛错 ⇒ 写进去就是**永远不可判定**的假判据 | 需改判据，但那会让本 REQ **永远判红** |
| T-11 | 复算器（不 import 被验包）与上游加载层检查（import 被验包）**分进程**（D122） | 「能不能被上游消费」的唯一真实答案只能问上游本人；同时复算必须保持纯净，否则实现 bug 会同时污染门与产物 | 需二选一；选 A 则判据变成「门自己写的解析器能不能消费」（自证） |
| T-12 | **不**要求组合门新增 `security-plan` 场景（D123） | 组合门是共享基础设施，改它会同时影响 REQ-004 等既有门；且组合门对 skill 枚举是动态的 | 需放开 `bin/verify-suite.mjs` 的改动面，并补一条判据 |
| T-13 | 用例 id **全局唯一** + **不与 `--cases` 输入集冲突**，但**不指定**具体编号 | REQ-007 的 D97/D82 教训；编号怎么分配是实现自由，写死即假判据 | 需改 AC-018 / §0.6 的真值表 |
