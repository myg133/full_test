## D165　`argv` 必须**完整可跑**：工具名 + 恰好一个完整绝对 URL + 结构合法

**决策**：

1. `argv` 是**非空字符串数组**（无空元素、无非字符串元素）；
2. `argv[0]` 是**工具名**：`loadtest` runner ⇒ `"loadtest"`；`python` runner ⇒ 自陈命令的第 0 个元素；
3. `argv` 里**恰好一个**元素是**完整绝对 URL**（`http://` / `https://` / `ws://` / `wss://` 开头），
   且它**逐字等于** `base_url`（去尾部 `/`）+ 目标路径；
4. 场景条目的 `base_url` 字段**逐字等于**环境文件的 `base_url`；
5. `loadtest` runner 的 `argv` 结构**恰为** F4.1 的规范形态 ⇒ **不得**有表外选项、**不得**有第二个位置参数。

**理由**：

- PROBE-FACTS C3：URL 是 `options.args[0]`，**多于一个** ⇒ `Too many arguments` 报错退出；
- PROBE-FACTS C4：URL 必须以 `http(s)://` / `ws(s)://` 开头，否则 `Invalid URL`；
- 「复制即可跑」是本 REQ 的核心价值 ⇒ 结构必须是**可核**的，不是「看起来像」。

**影响面**：F4.1；AC-009。

## D166　方法与路径必须**分离**

**决策**：

1. `argv` 里 `-m` **恰好出现一次**，其下一个元素 == 方法（**大写**）；
2. 方法 == `target` 的方法；若 `args.method` 存在，则**用它**（**大写**）；
3. 路径（`target` 里空格后那段）**只**出现在那个绝对 URL 元素里，`argv` 的**其它**元素**不得**含该路径。

**理由**：

- PROBE-FACTS D4：`target` 里**含方法** ⇒ 方法 ⇒ `-m`，路径 ⇒ URL 的 path 部分；
- 方法混进 URL（或路径混进 `-m`）⇒ 工具要么报错、要么打出**错误的方法** ⇒ 压出来的不是你想压的。

**影响面**：F4.1；AC-010。

## D167　多段画像**每段一条 invocation**（不许合并）

**决策**：

1. `invocations` 的**条数** == `profile.steps` 的**条数**；
2. 第 i 条的 `step_index` == **i**（**顺序不排序、不归并**）；
3. 第 i 条的 `duration_s` / `concurrency` **逐字等于** `steps[i]` 的同名值；

- 「步序本身就是语义」（REQ-009 `profile-rules.md` §1）⇒ 顺序也是契约。

**影响面**：F3.3；AC-011。

## D170　`-t` / `-c` 逐字映射该段的时长与并发

## D171　`args.timeout_s`（**秒**）→ `-d`（**毫秒**）：**×1000**

**决策**：

1. 模型 `args` 有 `timeout_s` ⇒ `argv` 里 `-d` **恰好出现一次**，其下一个元素 ==
   `String(Math.round(timeout_s * 1000))`；
2. 模型 `args` **没有** `timeout_s` ⇒ `argv` 里**不得**出现 `-d`。

**理由**：

- PROBE-FACTS C2：`-d` = timeout，**单请求**、**毫秒**；
- PROBE-FACTS C10 / D6：`timeout_s`（秒）**≠** `-d`（毫秒单请求超时），
  而且它**也不是**压测总时长（那是 `-t`）⇒ **三件事不能混**；
- 这是本 REQ 最容易搞错的一处（审门清单 **D1**）⇒ 契约必须把换算**写死**。

**影响面**：F4；AC-015。

## D172　`--rps` / `-k` 逐字映射

**决策**：

1. 模型 `args` 有 `rps` ⇒ `--rps` **恰好出现一次**，其下一个元素 == `String(rps)`；无 ⇒ **不得**出现 `--rps`；
2. 模型 `args` 的 `keepalive == true` ⇒ `-k` **恰好出现一次**；

**影响面**：F4；AC-016。

## D174　`python` runner **必须自陈完整命令**（`args.command` 是**完整 argv 数组**）

**决策**：

1. `args.command` 必须**存在**，且是**非空字符串数组**；缺失 / 是字符串 / 含空元素 ⇒ **rc=1** + 点名 `command`；
2. 命令里允许占位符 `{duration_s}` / `{concurrency}`，**必须**被该段取值替换；
   其它 `{...}` 占位符 ⇒ rc=1（点名）；
3. 计划里该场景的 `argv`：以自陈命令（替换后）为**前缀**，**含有**该段的 `duration_s` 与 `concurrency`
   的值元素，**不得**残留占位符；多段时各条 `argv` **互不相同**；

## 门侧技术纪律（**不占决策号**；对应需求方审门清单 `GATE-CHECKLIST.md`）

1. **sha 钉版**：脚本自算 sha256 与 `QA012_SCRIPT_SHA` 比对；不符 ⇒ `0 PASS / 1 FAIL` 退出。
2. **三态**：`PASS` / `FAIL` / **不可判定**（不可判定 ≠ 通过，退出码一律非 0）。
3. **条数动态取**：判据条数取 `acceptance.md` 的 `### AC-` **实际条数**；
   决策号取 `decisions.md` 的 `^## D[0-9]+` **实际集合**（按**数值**排序，不写死）。
4. **失败键口径**：判定失败时输出**必须**以 `FAIL <AC-xxx>` 开头的一行
   ⇒ 外部探针取 `^FAIL` 行做差集（**PASS / UNDEC 行里也有 AC 编号，混进来会让基线键集合变成全集**）。
5. **检测口径 = 新增失败键**（变异运行的失败键 **减去** 基线失败键），**不用对称差**。
6. **只读被验包**：一切变异在**副本**上做；门跑完被验包**零新增零改动**。
7. **变异体套件**：**≥20 个正控** + **≥1 个负控**（无害改动 ⇒ 必须**未检出**）。
   注入方式**分两类**：
   - **产物型** ⇒ 入口脚本包装（shim）：原实现 move 成 `plan-load-run.real.mjs`，
     包装层跑完原实现后篡改**产物**；
   - **静态文件型** ⇒ **先改副本里的文件再跑门**（包装层碰不到被验包的静态文件）。
   ⚠️ **包装层必须保留原权限位**（否则「可执行位」判据把每个变异体都判红）；
   ⚠️ **篡改未生效只打标记、不改退出码**（否则门把「合法形态不被接受」判红 ⇒ 污染全部判定）；
   ⚠️ **篡改代码必须 JS 内联**（node 跑 Python 语法的 `.mjs` 会 exit 3）。
8. **退出码**：`0` = 全通过；`1` = 有 FAIL / 不可判定 / 变异逃逸 / 负控失败 / sha 不符 / 门自身 stderr 有 bash 错误；`2` = 用法错误。
9. **可被覆盖的坑**：
   - 复算器**不得 import 被验包的任何模块**（否则等于用被验实现验证被验实现）；
   - 「能不能被上游消费」只能问上游本人（**单独进程**实跑，拿**真实退出码**）；
   - 门**不得**写「上游会拦」而上游其实不拦
     （实测：`plans/` 对上游无影响、`suite.json` 字段集封闭、计划内容上游**一条都不管**
     ⇒ 计划的一切内容**全部由门判**）；
   - 门**不得**要求压测工具能跑（本 REQ **不执行** ⇒ `--dry-run`/真跑必然不满足）
     ⇒ 落点是**文件系统与真实退出码上的外部证据**。
10. **环境变量**：`QA012_SCRIPT_SHA`（sha 钉版）/ `REQ012_NO_MUT=1`（跳过变异体套件）/
    `QA012_WORK_ROOT`（工作目录父目录）/ `QA012_KEEP_WORK=1`（保留工作目录）。
11. **上游模块缺失 ⇒ 判【不可判定】**，不许判 FAIL（环境问题 ≠ 实现违约；不可判定 ≠ 通过 ⇒ 退出码仍非 0）。
12. **不许判上游对整个项目根 rc=0 之外的任何东西** —— 本 REQ 的夹具**已预置**
    `environments/_schema.json` / `cycles/` / `.gitignore` ⇒「整个项目根 rc=0」在本 REQ
    是**可满足**的判据（与 REQ-009 不同，REQ-009 那三个前置不在其写入范围内）。
13. **决策号核对必须「逐个字面量各算各的」**（REQ-007 的 F-01 同类漏洞）：
    ①**每一个范围字面量自身**展开后的集合 == 实际决策号集合；
    ②文件里出现的**决策号并集** == 实际决策号集合；③不得出现本 REQ 之外的决策号。
14. **数组长度自检**：变异体的多个数组（`MUT_NAMES` / `MUT_CODE` / `MUT_TARGETS` / `MUT_MODE` / `MUT_FILE`）
    **逐条对齐**；进循环前比长度，不等就**明确报红退出**（不许让 bash 崩在数组下标上）。
15. **`${!var}` 用 `${!var-}`**（带默认值）—— 否则 `set -u` 下未定义变量会让**门自己**抛 bash 错误
    ⇒ 静默影响判定。
16. **门自身 stderr 自检**：全量留痕；出现 bash 错误行（`行 N:` / `line N:` / 未绑定变量）
    ⇒ 判红并退出码非 0。
17. **校验器必须有行为护栏**（审门清单 **D0**）：门**实跑** `check-load-run.mjs`，
    并验证「篡改计划 ⇒ 它判红（rc=1）」—— **只查「存在且非空」不算**。
