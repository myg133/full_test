## 遗留项登记（D45）

| # | 遗留项 | 理由 |
|---|---|---|
| L-1 | **F-10 版本前导零被接受**（`1.02.0` 视作 `1.2.0`） | AC-002 的版本格式只要求 `<数字>.<数字>.<数字>`，前导零不违规；逐段数值比较下二者等价，属**语义选择**而非缺陷 |
| L-2 | **软链安装形态**（`syncDir` 对符号链接做 `symlinkSync` 重建） | AC-024 的指纹按**文件内容**算，软链**目标**变化不会被察觉；本 REQ 只承诺"不得改动真实安装根"，不承诺软链目标不变 |
| L-3 | **非原子写竞态**（`writeJsonFile` / 锁文件无 tmp+rename） | 并发下可能读到半截文件；验收门是**串行**跑批，本 REQ 不覆盖 |
| L-4 | **`regression-plan.json` 的 `cycle_id` 与轮次目录名的关联** | 父会话裁定：`cycle_id` 由**输入**派生、与目录名**解耦**（AC-020 的硬要求优先）。「两者要不要成为新不变量」是**跨产物**的目录契约扩展 → **下一个 REQ 正式立判据**，本 REQ 不临时加判据（判据条数守恒） |
| L-5 | **组合门在调用方 `--root` 下累积 `.verify-work/<pid>-<ts>`（每次约 1MB）** | 组合门必须把包装到 `--root` 并在其中实跑跨 skill 场景 ⇒ **必然**要在该根下写东西（契约内的必然，不是越界）；真正的隔离红线是 **AC-024**（不动真实安装根）✓。累积增长属**工程卫生**问题，不是正确性问题 → 建议下个 REQ 加子项「跑完后清掉自己的 scratch 目录」 |
| L-6 | **`verify` 忽略 `TEST_AGENT_SKILLS_DIR`** | **不与 AC-024 矛盾**：`verify` 的契约是"装到临时根、**不碰真实安装根**"，**故意**不使用任何指向真实安装根的环境变量，是它能保证隔离的前提。需要校验某个已装副本时用 `verify --root <该副本目录>`；建议 README 写明（Dev 侧） |
| L-7 | **`check-plan.mjs` 的行为从未被门执行** | 门只对它做「存在且非空」+ `node --check`（语法），**从不运行它** → 自洽校验器的行为无护栏。补它需要新夹具与新子项 → 登记为后续 REQ 候选（本轮不扩判据面） |

**任何"脚本全绿的结论都必须钉版本** —— 同一批变异体在不同版本的脚本上结论可以不同（D34）。
