## D45 明细（第一轮独立验收的逐条订正）

> 记号：`G-x` = 验收门实现缺陷；`P-x` = 判据正文与实现的口径不一致/覆盖不足；`F-8/F-9` = 判不了定义的契约缝隙。
> 每条格式：问题 → 根因 → 修法 → 影响。

### G-1　AC-001 的 description「非空」检查太宽 → 放行空 description（逃逸）

- **问题**：`description: ""` 能过门（实测 28 PASS / 0 FAIL）。
- **根因**：`grep -qE '^description:[[:space:]]*[^[:space:]]'` —— `""` 的**第一个引号**就满足"非空白字符"。
- **修法**：新增 `frontmatter.mjs`，取 frontmatter 里 `description:` 的**值**再判空（块标量 `|`/`>` 取缩进块，块空即空；普通标量剥引号，`""`/`''` 判空）。正文同步写明该口径。
- **影响**：**堵住逃逸**，基线不受影响（交付 `SKILL.md` 用的是 `description: |` + 缩进块 → 仍判非空）。

### G-2　AC-019 的「before 指纹」取晚了 → 幂等写回输入不可见（逃逸）

- **问题**：实现若把 `cases.json` **幂等**改写（写回内容与原文件相同），门查不出来。
- **根因**：before 指纹取自**共享夹具**，而门在更早的步骤已跑过一次 `plan-regression.mjs` —— 污染被"前一次跑"吸收；带时间戳的非幂等写回能判红，证明**检出能力存在、只是被时序抵消**。
- **修法**：AC-019 **自己复制一份** `cases.json` / `CHANGELOG.md`，用**副本**跑，比对**副本**的前后 sha256。

### G-8　AC-025 把「变异体注入失效」等同于「逃逸」（假阳性 + 判据倒置）
