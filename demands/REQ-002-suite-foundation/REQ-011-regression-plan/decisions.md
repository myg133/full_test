| D35 | 2026-11-12 | **① R2 的影响面判定必须有「可独立重算」的依据**：变更条目的影响面来源限定为**三种可复算的形式** —— 需求条目引用 `@R-<n>`、用例引用 `@TC-\d{3}`、维度引用 `@dim:<name>`（显式）或维度 `applies_when` 信号词命中（隐式）；**② 选中用例的定义** = `affected(case) ∧ ¬method_blocked(case)`，`method_blocked` = 变更条目正文命中该用例所用方法的 `not_applies_when`；**③ `selected` / `needs_review` 两集合必须互斥** | ① R2 的产出是**一份选样结论** —— 漏选会漏测（不可容忍），多选只多花时间（可容忍）。因此判定口径必须**可证伪**：不能是"实现说了算"，必须能从**输入 + 库 + 计划自记的变更条目**独立重算出来。② 现有 R1 的两份库（`dimensions.json` 11 项 / `methods.json` 9 种）此前**没有任何运行时消费者** —— 本决策让它们第一次成为 R2 选样的判定依据，这是 REQ-006 资产的实际兑现。③ `not_applies_when` 命中意味着**该方法在本次变更场景下不适用** → 影响面**判不了** → 按本套件一贯纪律（"判不了就说判不了"，REQ-006 AC-008 / D27）必须交给人复核，**不得**静默当成"不受影响"。互斥是这条纪律的形式化：一条用例不能既"确定重跑"又"存疑待复核" |
| D36 | 2026-11-12 | **① 影响面判不了时必须显式列出且不得假装覆盖**：既无显式引用、正文也未命中任何维度/方法信号的变更条目 → 进 `undecidable_changes[]`，且**不得**让任何用例因它进 `selected`；② 存在此类条目时 `summary.impact_complete` 必须为 `false`；③ changelog 里引用了输入中不存在的需求条目 / 用例 id → **报错退出（退出码 1）并点名那个 id**，不得静默忽略 | ① "静默忽略坏引用" = 悄悄漏测，是本套件最不能接受的一类失败（与 REQ-006 的 D27「产出缺失必须标成 ERROR」同源）。② 影响面不完整却报"完整"，是**结论造假** —— 数字可以承载假陈述（REQ-005 的 D25 ⑬⑭ F-A 实测），所以完整性必须是一个**被声明的字段**，而不是靠读者推断。③ 静默忽略与"判不了"是两回事：坏引用是**输入错误**（该报错），判不了是**输入合法但信息不足**（该标注）—— 两者必须分开，不能都塞进 `undecidable` |
| D37 | 2026-11-12 | **① `regression-plan.json` 写在轮次目录内**（`test-assets/cycles/<cycle_id>/`，与 `cycle.json` 同级）；**② `regression-plan` 不得自己实现轮次状态写入**，一律经 `test-case-design/scripts/cycle-state.mjs`（REQ-002.5a 的硬约束）；③ R2 的 `round_type` = `regression`，变更影响分析落在 `design` 阶段；**④ 轮次状态只经脚本写这条硬约束，对本 REQ 是跨 skill 依赖 —— 组合门必须实跑这条路径** | ① 产物与它所属的轮次绑在一起（架构文档 §1.2：R2 的核心产物是 `regression-plan.json`）；放在轮次目录里，它与 `cycle.json` 共享同一 `cycle_id`，追溯链不需要第二套寻址。② 轮次状态写入权**只归脚本** —— 若 `regression-plan` 自己写 `cycle.json`，就出现了第二个写入者，REQ-002.5a 收口的整个目的（写入权收口）作废。④ 这条依赖是**硬**的（`test-execute/scripts/lib/cycle.mjs:20` 在运行时解析 `../../../test-case-design/scripts/cycle-state.mjs`）—— 版本错配会让轮次推进**静默失效**，下游报的是业务错，agent 会照着去改自己的用例 → 死循环（登记表已登记该风险）。故组合门**不得**只检查文件存在，**必须实跑**这条路径 |
